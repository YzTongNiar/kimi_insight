3. 算子瓶颈与优化优先级

P Attention ChunkKdaFwd → FusedInferAttentionScore优先检查 KDA 的 kernel 融合、KV/中间张量读写、布局转换和 tiling；并将 Attention 计算与通信等待流水重叠。
P MoE GroupedMatmul → DequantSituQuant / DynamicQuant → QuantBatchMatmulV3重点优化专家 token 聚合、小矩阵利用率、量化与 matmul 融合，以及 token permute；同时优化 all-to-all/dispatch/combine 与专家计算的重叠。
D Attention FlashMlaWithKvcache → RecurrentKda → AttnResFwdFused优先检查 KV cache 访问合并、cache layout、单 token 向量化、MTE 利用率和 launch/同步固定开销。
D MoE GroupedMatmulSituQuant → GroupedMatmul → QuantBatchMatmulV4/V3针对 decode 的小 token batch 选择低延迟 tiling，融合 grouped matmul 与 situ quant，并检查 dispatch/combine 的搬运和专家负载均衡。

5. 统计口径

阶段时间、计算和通信来自 step_trace_time.csv；访存/计算来自 kernel_details.csv 的 MTE、MAC、标量和向量计数器；Attention/MoE 来自 op_statistic.csv 的 Total Time 汇总。算子累计时间存在并行重叠，适合做负载构成和优化排序，不等同于串行阶段时延。
